# 引き継ぎ：カード右下「パラメータの割合」→ ダメージ計算のスレッドへ（2026-11-22）

2.10 のスレッド（カードの表現の統一）で、カード右下の「1か月で更新できる見込み」の段を、**パラメータのバランス**の図に置き換える試作をした。図の見た目はほぼ固まった。いまは**理想のバランス（式から出す値）がない**ため、ここから先はダメージ計算のスレッドの結果待ちになる。このメモは、そのスレッドに渡すもの。

---

## 1. 決まったこと（持ち主と）

**何を見せるか**
- いちばん見せたいのは「各パラメータのバランス」。バランスがピッタリか、ずれが大きいかが分かればよい。量・運・実数は削る
- 見せ方は**割合**（合わせて100%）。ひとつが増えると、ほかの割合が減って見えるのは**狙いどおり**（バランスに関係ない情報を落とすため）
- **勧めない**。「会心ダメがあと3回分ほしい」のような言葉や、一致度の点数は出さない。今と理想の割合を並べるだけ（事実ベース）
  - 理由：アプリはバフや凸をすべては扱えないので、わざと無凸餅の理想から外している人もいる
- 図は2つとも採用候補（`#card2` で切り替え。どれも持ち主は「結構好き」）
  - **円**：今の輪＋外の軌道に、理想の区切りを金の星
  - **100%の帯**：今の帯＋上の細い線に、理想の区切りを金の星。星から今の区切りへ細い曲線
  - 理想の目立たせ方は3案（控えめ／星を大きく光らせる／＋理想の細い輪・帯）。Claude のおすすめは「星を大きく光らせる」

**理想の決め方**
- 比べる相手は**無凸餅**（無凸・モチーフ武器 精錬1）の理想に**固定**する。誰と比べても同じ物差しにするため
  - 凸する人は対象外。または凸の分は見る人が頭の中で読み替える
- **アタッカー・サブアタッカーではチャージを考えない**。カードはショーケースとして割り切る（幽境での実用性は犠牲にする）
  - チャージは理想に入れず、図からも外す
- 式がないキャラは、今の割合だけを出す。役割が分からないので、チャージも入れる。UID がなければ空けて、UID での取り込みを促す

**まだ決めていないこと（式のスレッドでの結果を見て決める）**
- **メインOPも理想で選ぶか**（Claude の案：選ぶ）
  - 選ぶなら、元素ダメ（杯）や冠の会心率／会心ダメの違いが、理想とのずれとして見える
  - 本人のメインOPに固定するなら、元素ダメの割合はいつも今と同じになる。その場合は図から外す
- **理想の強化の回数**
  - 割合だけを見るので、総量そのものは出ない
  - ただ、回数で理想の形は少し変わる（回数が多いほど、伸ばす先が変わることがある）
  - 案：決まった標準の回数（よく育った無凸餅）で1つの形に固定する。A（固定の物差し）の考えに合う
- サポート・ヒーラーなど、ダメージが主でないキャラの理想をどうするか

## 2. 単位：「サブOP何回分」（キャラ全体の値）

今も理想も、同じ単位に直してから割合にする。**キャラ画面の最終値から、最初からある分を引いて、サブOP 1回の最大の伸びで割る**。

| パラメータ | 回数への直し方 |
|---|---|
| 会心率 | (最終値 − 5) ÷ 3.89 |
| 会心ダメ | (最終値 − 50) ÷ 7.77 |
| 元素チャージ効率 | (最終値 − 100) ÷ 6.48 |
| 元素熟知 | 最終値 ÷ 23.31 |
| HP・攻撃 | (最終値 ÷ 基礎 − 1) × 100 ÷ 5.83 |
| 防御 | (最終値 ÷ 基礎 − 1) × 100 ÷ 7.29 |
| 元素ダメ | 最終値 ÷ 5.83（サブOPにないので、攻撃%と同じ値で割ると決めた） |

- 基礎とは、キャラの基礎の値と武器の基礎攻撃力を足したもの（Enka の `fightPropMap` の 1・4・7）
- この単位では「会心率：会心ダメ＝1：2」が同じ長さになる
- 図に出すパラメータは、キャラの有効OPに対応するもの（HP%→HP、攻撃%→攻撃 …）と、そのキャラの元素ダメ

**理想も「キャラ画面の値」で返してほしい**
- 今の値は、UID のキャラ画面の値（突破・武器・聖遺物・セットの常時効果込み）
- チームのバフや、条件付きの武器・天賦の効果は、キャラ画面に出ないので今の値には入っていない
- なので理想も、**最適な配分を決めるときには条件付きの効果も使うが、図に出す値はキャラ画面に出る分だけ**にする。そうでないと、今と理想で数え方がずれる
  - 例：理想を決める計算には「元爆の後の会心ダメ+28%」を入れるが、返す会心ダメの値には入れない

## 3. 式のスレッドに頼みたいもの

キャラごとに、**無凸餅の理想**を上の単位で返すもの。

```js
// 例：フリーナ。キー＝パラメータ（HP / ATK / DEF / CR / CD / ER / EM / 'DMG_水' など）、値＝サブOP何回分（キャラ全体。上の表の直し方）
c.idealRoll = { HP:22, CR:17.5, CD:26, 'DMG_水':8 };
```

- カードは `c.idealRoll` を見て描く。キーがないパラメータは理想なしとして扱う
  - アタッカーのチャージは、キーを入れなければ図から外れる
- いまは `#card2` の見本だけに、仮の値を手で入れている（`build_card.py` の `cc2Samples` の `smU.idealRoll` と `s100U.idealRoll`）
- 本番では、キャラ名（またはキャラ id）から理想を引く表か関数があるとよい。例：`IDEAL[name]`、`idealRollOf(c)`
- 前提（武器・天賦Lv・キャラLv・メインOP・セット・強化の回数・想定チーム）も一緒に残してほしい。アプリ側の説明に使う

## 4. いま手元にあるデータ

**UID で取り込んだキャラ**：`c.uidStat`（`build_card.py` の `enkaStat`。2026-11-22 から）

```js
c.uidStat = {
  fp:   { HP, ATK, DEF, CR, CD, ER, EM, HEAL, PHYS, 'DMG_炎'…'DMG_氷' }, // キャラ画面の最終値。%は小数第1位の%、HP・攻撃・防御は実数。0 の治療・物理・元素ダメは入れない
  base: { HP, ATK, DEF },          // 基礎の値（fightPropMap の 1・4・7）
  cons: 2,                         // 凸数
  lv:   90,                        // キャラのLv
  w:    { id, lv, r, star }        // 武器：Enka の itemId・Lv・精錬・★
}
```

- `base` は 2026-11-22 の後半に足した。それより前に取り込んだショーケースには入っていないので、取り込み直すと入る
- 聖遺物：`c.pieces[slot]`（`slot` は flower / plume / sands / goblet / circlet）
  - `main`：メインOPのキー
  - `subs`：`[{s, v, off}]` の並び
  - `lv`：強化のLv
- 有効OP：`c.eff`（例：`['HP%','CR','CD','ER']`）
- キャラの元素：`skyElem(c)`（`src/lab.html`）
- 前からあるダメージの試作：`DMG_MODELS`（フリンズだけ）、`dmgTotal`、`dmgCompare`（`build_card.py`）。これは「この1個に替えたら何%変わるか」を見るもので、理想の配分は出さない

## 5. 図のコードの場所

- `tools/build_card.py` の、カード右下の段（`if(UPM==='br')` の中）
  - `window.CC2_OPT.pb` の `PX`（円・仕上げ）と `BX`（100%の帯・仕上げ）
  - 理想の目立たせ方は `ie`（`n` 控えめ／`s` 光らせる／`r` ＋細い輪・帯）
- ほかに残している試作：`B2`／`B3`（横棒・回数）、`P2`／`P1`（素朴な円）、`U`（実際の値の表）
- 確認方法
  - `python3 tools/build_pages.py`
  - `python3 -m http.server 8000 --directory _site`
  - `http://localhost:8000/?v=4#card2` を開き、「右下の段（試作）」で切り替える
  - 見本4・5は UID と仮の理想、見本6は UID・式なし
- 本番のカードはまだ「1か月で更新できる見込み」のまま。図を本番に出すのは、理想が出せてから
