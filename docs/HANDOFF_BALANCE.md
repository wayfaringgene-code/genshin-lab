# 引き継ぎ：カード右下「聖遺物のパラメータの割合」→ ダメージ計算のスレッドへ（2026-11-22、11-23 に改訂）

2.10 のスレッド（カードの表現の統一）で、カード右下の「1か月で更新できる見込み」の段を、**聖遺物のパラメータの割合**の図に置き換える試作をした。

- 図の見た目はほぼ固まっている
- 「今の割合」は、聖遺物の値だけで描ける（UID は要らない）
- 図には**理想の割合**を重ねる仕組みもすでにある。ただ、理想の値を出す方法がまだない

理想は長期の課題とする。次のどちらか、または両方で埋める。

- ダメージ計算のスレッドで、式から出す
- 各ユーザーに登録してもらう

このメモは、ダメージ計算のスレッドに渡すもの。

---

## 1. 決まったこと（持ち主と）

**何を見せるか**
- 見せたいのは「各パラメータのバランス」。ピッタリか、ずれが大きいかが分かればよい。量・運・実数は削る
- 見せ方は**割合**（合わせて100%）
  - ひとつが増えると、ほかの割合が減って見える。これは**狙いどおり**（バランスに関係ない情報を落とすため）
- **勧めない**
  - 「会心ダメがあと3回分ほしい」のような言葉や、一致度の点数は出さない
  - 今と理想の割合を並べるだけ（事実ベース）
  - 理由：アプリはバフや凸をすべては扱えない。わざと理想から外している人もいる
- **今の割合は聖遺物の分だけ**（5部位のメインOP＋サブOP）
  - 武器のサブステ・突破・セット効果は、今の図には入れない
  - これらは**理想を計算する側で吸収する**（2章）
- 図は2案とも残す（`#card2` で切り替え）
  - **円**：今の輪に、理想の区切りを金の星で重ねる
  - **100%の帯**：今の帯に、理想の区切りを金の星で重ねる

**理想について**
- 理想は長期の課題。式から出すか、ユーザーに登録してもらう
- 図に理想を重ねる機能は残す。理想がないキャラは、今の割合だけを出す
- 式から出すときの前提（持ち主と決めたもの）
  - 比べる相手は**無凸餅**（無凸・モチーフ武器 精錬1）に**固定**する
  - **アタッカー・サブアタッカーではチャージを考えない**（カードはショーケースとして割り切る）
- 認めている弱点（ユーザーの登録で補う考え）
  - モチーフ以外の武器の人は、正しく組んでいても理想からずれて見える
  - 「なぜ理想がこの形か」（例：武器が会心率を補っている）は図から読めない

## 2. 単位：「サブOP何回分」（聖遺物の分）

今も理想も、聖遺物の値を**サブOP 1回の最大の伸び**で割って回数に直し、そのうえで割合にする。

| パラメータ | 1回の最大の伸び |
|---|---|
| HP% | 5.83 |
| 攻撃力% | 5.83 |
| 防御力% | 7.29 |
| 元素熟知 | 23.31 |
| 元素チャージ効率 | 6.48 |
| 会心率 | 3.89 |
| 会心ダメ | 7.77 |
| 元素ダメバフ | 5.83 |

- メインOP（+20）を上の値で割ると、どれも**ちょうど8回分**になる
  - HP%・攻撃% 46.6、防御% 58.3、熟知 186.5、チャージ 51.8、会心率 31.1、会心ダメ 62.2
  - 元素ダメのメイン 46.6 は攻撃%と同じなので、5.83 で割るのがほかとそろう
- この単位では「会心率：会心ダメ＝1：2」が同じ長さになる
- **実数（HP・攻撃・防御）は入れない**
  - 花・羽のメインは誰でも同じなので、バランスの差を生まない
  - 実数のサブは小さいので外す
  - そのため基礎の値も UID も要らない
- 図に出すパラメータ：キャラの有効OPのうち上の%のもの＋そのキャラの元素ダメ
  - 元素ダメは、杯がその元素ダメでなければ 0%
- 治療効果・物理ダメ（メインOP）は図に出ない
- +20 未満の部位も、メインOPは +20 の値で数える（サブOPは今の値）

## 3. 式のスレッドに頼みたいもの

キャラごとに、**無凸餅で聖遺物をどう振り分けるのが理想か**を、上の単位で返すもの。

- 武器（モチーフ）のサブステ・突破・セット効果・条件付きの効果（元爆の後のバフなど）は、**最適な振り分けを決める計算の中で使う**
- **返す値は聖遺物の分だけ**にする。今の図と同じ数え方にするため

例：武器が会心ダメを持つなら、計算の中でそれを入れる。そうすると聖遺物の会心ダメの理想は小さめに出る。

```js
// 例：フリーナ。キー＝パラメータ（HP / ATK / DEF / CR / CD / ER / EM / 'DMG_水' など。HP・ATK・DEF は % のこと）
// 値＝聖遺物の分のサブOP何回分（メインOP＋サブOP）。割合にして使うので、効くのは比だけ
c.idealRoll = { HP:9, CR:10.5, CD:10, 'DMG_水':8 };
```

- カードは `c.idealRoll` を見て描く。キーがないパラメータは理想なしとして扱う
  - アタッカーのチャージは、キーを入れなければ図から外れる
- いまは `#card2` の見本だけに、仮の値を手で入れている（`build_card.py` の `cc2Samples` の `smU.idealRoll` と `s100U.idealRoll`）
- 本番では、キャラ名（またはキャラ id）から理想を引く表か関数があるとよい。例：`IDEAL[name]`、`idealRollOf(c)`
  - ユーザーの登録も、同じ形（パラメータ→回数、または割合）で受ける想定
- 前提（武器・天賦Lv・キャラLv・メインOP・セット・強化の回数・想定チーム）も一緒に残してほしい。アプリ側の説明に使う

**未決のこと（式のスレッドの結果を見て決める）**
- **メインOPも理想で選ぶか**（Claude の案：選ぶ）
  - 選ぶなら、杯の元素ダメ／攻撃%、冠の会心率／会心ダメの違いが、理想とのずれとして見える
  - 本人のメインOPに固定するなら、メインの分は今と理想で同じになる。元素ダメは図から外してよい
- **理想の強化の回数**
  - 割合だけを見るので、総量は出ない。ただ、回数で理想の形は少し変わる
  - 案：決まった標準の回数（よく育った無凸餅）で1つの形に固定する
- セットの選び方（本人のセットに固定するか、理想のセットにするか）
- サポート・ヒーラーなど、ダメージが主でないキャラの理想をどうするか

## 4. いま手元にあるデータ

**聖遺物**（どの取り込み方でもある）
- `c.pieces[slot]`（`slot` は flower / plume / sands / goblet / circlet）
  - `main`：メインOPのキー
  - `subs`：`[{s, v, off}]` の並び
  - `lv`：強化のLv
- 有効OP：`c.eff`（例：`['HP%','CR','CD','ER']`）
- キャラの元素：`skyElem(c)`（`src/lab.html`）
- メインOPの +20 の値：`MAIN_NUM`（`build_card.py`）
- サブOPの1回の伸び：`ROLL`（`src/lab.html`）

**UID で取り込んだキャラ**：`c.uidStat`（`build_card.py` の `enkaStat`）

今の図には使っていない。将来「自分の武器での理想」を出すときに使える。

```js
c.uidStat = {
  fp:   { HP, ATK, DEF, CR, CD, ER, EM, HEAL, PHYS, 'DMG_炎'…'DMG_氷' }, // キャラ画面の最終値（突破・武器・聖遺物・セットの常時効果込み）
  base: { HP, ATK, DEF },          // 基礎の値（fightPropMap の 1・4・7）。11-22 後半から
  cons: 2, lv: 90,                 // 凸数・キャラのLv
  w:    { id, lv, r, star }        // 武器：Enka の itemId・Lv・精錬・★
}
```

**前からあるダメージの試作**
- `DMG_MODELS`（フリンズだけ）、`dmgTotal`、`dmgCompare`（`build_card.py`）
- 「この1個に替えたら何%変わるか」を見るもので、理想の振り分けは出さない

## 5. 図のコードの場所

- `tools/build_card.py` の、カード右下の段（`if(UPM==='br')` の中）
  - `window.CC2_OPT.pb` の `PX`（円）と `BX`（100%の帯）

- 前の試作も残している（キャラ全体の値を使う形。UID が要る）
  - `B2`／`B3`（横棒・回数）
  - `P2`／`P1`（素朴な円）
  - `U`（実際の値の表）
- 確認方法
  - `python3 tools/build_pages.py` で組み立てる

  - `http://localhost:8000/?v=5#card2` を開き、「右下の段（試作）」で切り替える
  - 見本4・5は仮の理想あり。ほかは理想なし
- 本番のカードはまだ「1か月で更新できる見込み」のまま
